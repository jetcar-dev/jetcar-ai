# 네이버 카페

현재 채팅에 연결된 제트카 플러그인의 `naver-cafe` MCP 도구를 사용한다. 도구가 보이지 않으면 Codex를 다시 열고 새 채팅에서 제트카를 선택하도록 안내한다. 셸에서 플러그인 실행 파일을 별도로 띄우거나 브라우저 UI로 대신 처리하지 않는다.

## 요청에 맞는 도구

| 요청 | 처리 |
| --- | --- |
| 로그인 상태 확인 | `check_cafe_login`을 호출한다. 다른 도구는 자체적으로 연결 상태를 확인한다. |
| 게시판 조회 | `list_cafe_boards`를 호출해 로그인한 계정에 보이는 게시판을 조회한다. `menuTree` 순서를 따르고 하위 게시판은 그룹 아래에 들여쓴다. 게시판 이름과 번호를 함께 보여준다. |
| 특정 게시판의 게시글 조회 | `list_cafe_articles`로 최신 글의 제목, 작성일, 링크와 필요한 본문을 조회한다. |
| 임시글 조회 | `list_cafe_drafts`에서 제목, 게시판, 저장 시간을 보여준다. 게시판 링크를 넘겨도 조회 범위는 카페 전체이므로 특정 게시판 요청은 반환된 목록에서 거른다. |
| 새 임시글 저장 | 아래 절차를 따라 `save_cafe_draft`를 호출한다. |
| 기존 임시글 수정 | `list_cafe_drafts`에서 대상을 찾아 `save_cafe_draft`를 호출한다. |

## 게시글 목록과 본문 조회

1. 알고 있는 게시판 링크를 `boardUrl`로 전달한다. 예를 들어 제트카 카페의 중고차 장기렌트카 입고 게시판은 `https://cafe.naver.com/f-e/cafes/23209962/menus/50`이다. 링크를 모르면 `list_cafe_boards`로 이름과 번호를 확인한다.
2. 전체 본문 요청은 `bodyMode: "full"`, 앞부분만 필요하면 `"preview"`, 제목·날짜만 필요하면 `"none"`을 쓴다. 공개 게시판은 바로 조회한다. 회원용 글이 필요하거나 로그인 없이 목록이 비어 있으면 `useLogin: true`로 해당 계정이 볼 수 있는 글을 조회한다. 로그인 안내가 오면 같은 호출을 반복하기 전에 필요한 연결을 해결한다.
3. 요청 건수만 가져온다. 페이지당 최대 50개이며, 더 필요하면 동일한 `pageSize`와 `nextPage`로 이어서 읽는다. `loginAction`이 있으면 연결 안내를 따르고, 일부 `bodyStatus`가 `loaded`가 아니면 목록은 보여주되 해당 본문은 조회되지 않았다고 구분한다. 채팅에 결과를 표시하며, 엑셀 파일은 사용자가 요청할 때 만든다.

## 새 글 임시저장

1. 사용자가 준 게시판 링크가 있으면 `boardUrl`로 사용한다. 이름이나 번호만 주면 `list_cafe_boards`에서 일치하는 항목의 링크를 사용한다. 카페를 따로 지정했거나 카페 홈 링크를 주면 해당 링크를 `cafeUrl`에 전달한다. 일치하는 게시판이 여러 개면 이름과 그룹 또는 번호로 후보를 보여주고 확인한다. 찾을 수 없으면 사용할 게시판 링크나 정확한 이름을 묻는다.
2. 사용자가 준 원고는 요청한 부분만 바꾼다. 차량 자료를 바탕으로 새 원고를 쓰거나 다듬을 때는 [차량 입고·홍보 글 작성](references/vehicle-posts.md)을 읽는다.
3. 원고 변환과 서식 구성은 [스마트에디터 ONE 스킬](../smart-editor-one/SKILL.md)을 사용한다. 필수 서식을 지원하지 않는 경우에는 카페 글쓰기 화면에서 넣는 방법을 안내하거나 적용 가능한 범위로 임시저장할지 확인한다.
4. 첨부를 직접 지정할 때는 `%LOCALAPPDATA%\Jetcar\NaverCafeMcp\photos`의 파일 이름을 사용한다. 개발 설정에서 `NAVER_IMAGE_DIR`를 지정했으면 그 폴더를 사용한다. Word·HWPX·HTML에서 가져온 내장 사진은 원고 ID로 함께 처리한다.
5. 임시저장 대상으로 확인된 게시판을 `boardUrl`로 사용한다. 파일을 그대로 저장할 때는 도구가 반환한 `documentId`를 `save_cafe_draft`의 `preparedDocumentId`에 전달한다. 직접 구성한 원고는 `structuredContent.draft`와 게시판을 전달한다. 같은 글을 여러 건 저장할 때는 동일한 ID 또는 같은 원고를 필요한 건수만큼 사용한다.

## 기존 임시글 수정

1. 같은 카페와 브라우저 계정의 임시글 목록에서 제목, 게시판, 저장 시각을 대조한다. 대조 후에도 여러 글이 일치하면 후보를 보여준다. 한 건을 찾으면 해당 글의 `temporaryArticleId`와 `boardUrl`로 저장한다. 조회에서 대상을 찾지 못하면 카페·계정·제목을 확인한다.
2. 제목을 바꿀 때만 `title`을 전달한다. `blocks`는 기존 본문 끝에 추가된다. 대표사진만 바꿀 때는 선택한 사진의 순번을 `representativeImage`로 전달한다. 순번은 기존 사진부터 세며 첫 사진은 1번이다. 문단이나 사진의 교체·삭제·재배치는 카페 글쓰기 화면에서 할 수 있다.

## 도구 응답 처리

브라우저 연결이 처음 필요하면 MCP 호출 중에 Playwright Extension 연결 화면이 열린다. 사용자에게 로그인된 카페 탭을 선택하고 **Allow**를 한 번 누르도록 안내한 뒤, 진행 중인 호출 결과를 기다린다. 게시판 조회에서 브라우저를 선택했다면 후속 임시저장에도 같은 `browser`를 전달한다. 재연결 요청이 진행 중인 작업과 관련 있으면 연결이 확인된 뒤 그 작업을 이어서 처리한다.

| 응답 | 조치 |
| --- | --- |
| `needs_cafe_url`, `needs_board_url` | 필요한 카페 홈 또는 게시판 링크를 요청한다. 게시판 이름이나 번호를 이미 알고 있다면 조회로 찾을 수 있는지 먼저 확인한다. |
| `needs_browser_choice` | 도구의 선택지를 보여주고, 선택한 값을 후속 호출의 `browser`에 사용한다. |
| `needs_naver_login` | 도구가 지정한 Chrome 또는 Edge 프로필에서 네이버에 로그인하도록 안내한다. |
| `needs_playwright_extension` | 네이버에 로그인한 브라우저에 [Playwright Extension](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm)을 설치하도록 안내한다. |
| `extension_connection_failed` | 이 요청의 후속 호출을 멈추고 끊긴 연결을 알린다. 사용자가 재연결을 요청하면 `check_cafe_login`에 `reconnect: true`를 전달하고, 연결 화면이 열리면 **Allow**를 한 번 누르도록 안내한다. |
| `draft_preparation_failed` | 글쓰기 설정 또는 스마트에디터 첨부 준비에서 실패했다. 도구가 돌려준 원인을 안내하고 해결한 뒤 다시 시도한다. 임시저장 요청을 보내기 전 실패이므로 저장 결과 확인을 위해 목록을 다시 조회할 필요가 없다. |
| 첨부 파일 오류 | 오류에 해당하는 파일명이나 폴더를 확인하고 사용자가 요청한 사진·MP4로 진행한다. |
| 쓰기 권한 오류 | 대상 게시판과 선택한 계정에 글쓰기 권한이 있는지 확인한다. 다른 게시판은 사용자가 지정했을 때 사용한다. |
| `saved_as_draft` | 저장된 제목과 게시판, 임시글 ID를 알려준다. 첨부 파일이 있으면 사진 장수와 대표사진 번호, 동영상 개수를 함께 전한다. 사용자는 카페 글쓰기의 **임시등록**에서 열 수 있다. |

응답이 끊기거나 저장 여부를 확인할 수 없으면 재호출 전에 같은 계정과 카페의 임시글 목록에서 제목·게시판·저장 시각을 확인한다. 기존 글의 본문이나 대표사진이 적용됐는지는 목록만으로 확인할 수 없으므로 필요하면 사용자가 임시등록 화면에서 확인하도록 안내한다. 이 스킬의 쓰기 작업은 임시저장까지다.
